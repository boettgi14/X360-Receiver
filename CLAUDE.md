# Project rules for Claude Code

- Design and status: `docs/DESIGN.md`. Protocol knowledge: `docs/PROTOCOL.md`. Read those first, then make changes, and keep them in line with the code.
- Every protocol statement carries a confidence level (source, unit-tested, hardware, hypothesis). New findings from real hardware replace hypotheses and go into `docs/PROTOCOL.md`.
- Do not present a statement as confirmed if it only comes from unit tests or sources.
- Tests: `python3 -I -m unittest discover -s tests` before every commit (on Linux or in WSL; the tests assume POSIX paths). After changes under `src/`: `npm run typecheck`, `npm run build` and the render test `tools/frontend_render_test.mjs` (it checks both UI languages).
- Privacy: usbmon sees the whole bus. Discard foreign devices immediately, store or log nothing. Only count input packets.
- Backend (root) writes only to the named sysfs paths and knows exactly these external calls: the fixed `modprobe usbmon`, `systemctl daemon-reload | enable --now | disable --now` exclusively for its own service `x360-receiver-poweroff.service` (all through `safe_exec.run_fixed` with a sanitized environment, without user input) and the USB commands of the short access (`00 00 00 40`, the presence request `08 00 0F C0` that follows a successful battery query, `00 00 08 C0`) to known receivers and slots 0 to 3. For the rumble test it also writes one force-feedback effect, write-only, to the `/dev/input/eventN` node that sysfs shows under a known receiver's slot interface (`x360w.rumble`; it never reads input). Outside Decky the plugin creates only `/etc/systemd/system/x360-receiver-poweroff.service` and `/var/lib/x360-receiver/`, only while the option "Turn off on shutdown" is switched on, owned by root (0644/0755), and deletes both when the option is switched off and when the plugin is removed. The plugin never deletes anything under `DECKY_HOME` (its settings, data and log folders stay behind). No free shell calls, no user input in commands.
- Decky files (`plugin.json`, `package.json`, `main.py`, `src/`) follow the official `decky-plugin-template`. The root flag is called `root` (Decky checks for exactly this string; `_root` is the template's switched-off placeholder). `dist/index.js` is build output and is regenerated with `npm run build`.
- Shutting down: Decky sends SIGKILL if the plugin process is still alive 5 s after SIGTERM, and its own socket reader can starve the plugin's event loop while it is being stopped (`docs/DESIGN.md`, section 5). Therefore `_unload` and `_uninstall` must never really suspend: no real `await`, no thread, no `asyncio.to_thread`. `tests/test_backend.py` checks this. Do not remove `x360w.loop_guard` or the exit watchdog in `_unload` without a journal from a device showing the plugin stopping on its own.
- Language: All documentation (README, design, protocol, comments, docstrings, test descriptions) is in English. Code identifiers: English.
- UI languages: The plugin UI is available in English and German and follows the Steam UI language (`navigator.language`, English as the fallback); the user can override it in the settings (stored in the backend as `language`). All UI text lives in `src/i18n.ts`; `en` is the base and `de` must match its shape. The Python backend is language-neutral: English technical messages, plus a `code` from `x360w.error_codes` (and the diagnostics verdict codes in `poweroff_unit`) for everything the frontend translates. New UI text goes into both languages, new backend codes into `src/i18n.ts` as well (`tests/test_i18n_contract.py` checks this). External programs run with `LANG=C`, so nothing depends on the system language.
- Releases: a one-line commit message in the style of the existing ones, a lightweight tag `vX.Y.Z`, a GitHub release named `Release vX.Y.Z` without a description, with the zip from `tools/make_zip.py` attached as `X360-Receiver.zip`. The version is in `package.json` (and `package-lock.json`).
