# Project rules for Claude Code

- Goal and plan: `PLAN.md`. Protocol knowledge: `docs/PROTOCOL.md`. Read those first, then make changes.
- Every protocol statement carries a confidence level (source, unit-tested, hypothesis). New findings from real hardware replace hypotheses and are carried over into `docs/PROTOCOL.md`.
- Do not present a statement as confirmed if it only comes from unit tests or sources.
- Tests: `python3 -I -m unittest discover -s tests` before every commit. After changes under `src/`: `npm run typecheck`, `npm run build` and the render test `tools/frontend_render_test.mjs` (it checks both UI languages).
- Privacy: usbmon sees the whole bus. Discard foreign devices immediately, store or log nothing. Only count input packets.
- Backend (root) writes only to the named sysfs paths and knows exactly these external calls: the fixed `modprobe usbmon`, `systemctl daemon-reload | enable --now | disable --now` exclusively for its own service `x360-receiver-poweroff.service` (all through `safe_exec.run_fixed` with a sanitized environment, without user input) and the USB commands of the short access (`00 00 00 40`, `00 00 08 C0`) to known receivers and slots 0 to 3. For the rumble test it also writes one force-feedback effect, write-only, to the `/dev/input/eventN` node that sysfs shows under a known receiver's slot interface (`x360w.rumble`; it never reads input). Outside Decky the plugin creates only `/etc/systemd/system/x360-receiver-poweroff.service` and `/var/lib/x360-receiver/`, only while the option "Turn off on shutdown" is switched on, owned by root (0644/0755), and deletes both when the option is switched off and when the plugin is removed. No free shell calls, no user input in commands.
- Decky files (`plugin.json`, `package.json`, `main.py`, `src/`) have been compared with the official `decky-plugin-template`, the frontend builds, the plugin now runs on the user's device, and the systemd service for shutdown works according to the user (status: see `PLAN.md`). The root flag is called `root` (Decky checks for exactly this string; `_root` is the template's switched-off placeholder). `dist/index.js` is build output and is regenerated with `npm run build`.
- Language: All documentation (README, PLAN, PROTOCOL, comments, docstrings, test descriptions) is in English. Code identifiers: English.
- UI languages: The plugin UI is available in English and German and follows the Steam UI language (`navigator.language`, English as the fallback). All UI text lives in `src/i18n.ts`; `en` is the base and `de` must match its shape. The Python backend is language-neutral: English technical messages, plus a `code` from `x360w.error_codes` (and the diagnostics verdict codes in `poweroff_unit`) for everything the frontend translates. New UI text goes into both languages, new backend codes into `src/i18n.ts` as well (`tests/test_i18n_contract.py` checks this). The user can override the detected language in the settings (stored in the backend as `language`). External programs run with `LANG=C`, so nothing depends on the system language.
